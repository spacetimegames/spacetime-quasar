== What works

All of this is on `main`.

* Dev shell: `nix develop` gives the pinned Rust 1.99.0 plus sccache, and mold on Linux only (xref:../adr/0001-toolchain-msrv-nix.adoc[ADR 0001], xref:../adr/0004-build-resources.adoc[ADR 0004]). `nix fmt` works.
* Cargo workspace: 12 `st-*` crate stubs, `tools/xtask` and `apps/spacetime-quasar` (a stub binary). It builds and passes fmt, clippy with `-D warnings`, and tests. It also checks on wasm32.
* CI (GitHub Actions) runs 9 required checks: `fmt`, `test (linux-x86_64)`, `test (windows-x86_64)`, `test (macos-aarch64)`, `wasm32`, `msrv`, `deny`, `docs` and `nix`. See xref:../adr/0003-ci-design.adoc[ADR 0003].
* Docs: the xref:../index.adoc[index] and stubs, ADRs 0001 to 0004, the product decision records PD-01 to PD-26, `AGENTS.md`, `README.adoc` and the xref:../60-contributing.adoc[contributing guide].

== In progress

* ADR 0005 brings wgpu forward to Phase 0 so the window becomes visible on Wayland (PR #9).
* The empty window (SPAC-96, PR #7) waits on that ADR.

== Next

Remaining Phase 0 work:

. Empty window visible on Wayland that resizes and closes cleanly (SPAC-96), run from the dev shell.
. Flake `packages.default` with runtime library wrapping, and flake `checks`, after the window lands. They make `nix run` start the game binary and give `nix flake check` the CI gates.
. The Phase 0 hands-on test note `docs/handoff/try/phase-0.adoc` and the owner test.
. The phase-gate review.

Phase 1 (Base crates) needs these ADRs:

* `nalgebra` vs `glam` boundary.
* Large-world coordinates and f32 vs f64. It uses the answered space-scale decision (PD-26).
* Determinism implementation.
* Command log and replay format.
* Data schema versioning.

== Known problems

* `nix run` does not work yet: the flake has no `packages` output.
* On NixOS the binary needs the dev shell to find the Wayland and X11 libraries, until the package wrapper lands.
* MSRV 1.88 is verified only in CI.
* The `nix` CI job only evaluates the flake until `checks` exist.

== Open owner questions

Needed before Phase N means the answer must exist before that phase starts.

* G2, controls (needed before Phase 2): devices and default bindings; target cycling; land/autopilot, hail and board keys.
* G7, combat (needed before Phase 2): laser model (instant beam with overheat vs travelling bolts, undecided); lead indicator; shield regeneration; what armour regions do; disable-and-board vs destroy; player death; escorts.
* G5, economy (basic needed before Phase 2, full needed before Phase 3): price formula, production and consumption, player impact, cargo units, starting credits and ship, commodity list, illegal goods.
* G9, traffic (basic needed before Phase 2): AI archetypes and traffic density per system.
* Later, needed before Phase 3: G4 navigation and jumps, G6 factions and law, G8 missions, G11 saves and sessions. Needed before Phase 5: G14 audio direction.
* Licence: deferred by the owner. All rights reserved meanwhile. To be decided at the first crate publication review or the MVP release, whichever comes first (open point #7).
* Open point #15, the native X11 test session, is parked until Phase 6.

G10 (space scale) is answered (PD-26) and feeds the Phase 1 large-world coordinates ADR.
