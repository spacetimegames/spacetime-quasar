== What works

All of this is on `main`.

* Dev shell: `nix develop` gives the pinned Rust 1.99.0 plus sccache, cargo-deny, wasmtime, and mold on Linux only (xref:../adr/0001-toolchain-msrv-nix.adoc[ADR 0001], xref:../adr/0004-build-resources.adoc[ADR 0004]). `nix fmt` works.
* Cargo workspace: 12 `st-*` crates (6 implemented, listed below; `st-render` drives the window; the other 5 are stubs), `tools/determinism`, `tools/phase1-demo`, `tools/xtask` and `apps/spacetime-quasar` (opens the window). It builds and passes fmt, clippy with `-D warnings`, and tests. It also checks on wasm32.
* CI (GitHub Actions) runs 10 required checks: `fmt`, `test (linux-x86_64)`, `test (windows-x86_64)`, `test (macos-aarch64)`, `wasm32`, `msrv`, `deny`, `docs`, `nix` and `determinism`. See xref:../adr/0003-ci-design.adoc[ADR 0003].
* `nix run github:spacetimegames/spacetime-quasar`, or `nix run` in a checkout, opens the visible window. `packages.default` is built with crane and wraps the Vulkan, Wayland, xkbcommon and X11 libraries through `RUNPATH`. `nix flake check` mirrors the CI gates that can run under Nix (fmt, nixfmt, clippy, test, bench build, doc, asciidoc, deny without advisories, wasm32); the `nix` CI job runs it.
* Window: a visible window through `st-render` (wgpu on Vulkan, ADR 0005) that closes on close or Escape; the owner hands-on test passed on 2026-10-11 on NixOS with COSMIC on Wayland, on both the RTX 3080 Laptop GPU and the integrated Intel GPU (xref:try/phase-0.adoc#_result[test result], xref:../20-platforms/nixos-cosmic.adoc[platform notes]).
* `st-rng`: stateless counter-based RNG (PR #17).
* `st-time`: fixed-step clock and frame-budget statistics (PR #20).
* `st-data` core: versioned RON envelope, migrations, canonical BLAKE3 hashes and diagnostics (PR #19).
* `st-platform` core: filesystem, clock, and a hot-reload watcher behind a feature (PR #21).
* `st-data` hot-reload wiring: `st_game::HotData` feeds the `st-platform` watcher into the `st-data` loader (feature `hot-reload`, off by default) with `Arc` snapshots, a valid batch applied atomically, and bad or removed files reported once without blocking others (SPAC-124).
* `st-math`: deterministic scalar math (`det`) and the camera-relative render origin (PR #25); from SPAC-123, Kepler orbits for on-rails bodies (elliptic only, fixed-iteration solver) and `f64` interpolation (lerp, nlerp, slerp, Hermite), with bit-pattern golden tests.
* `st-sim` (minimal): commands, fixed step, state hash and three scenarios, plus the `determinism` harness in `tools/determinism` (PR #26; xref:../62-determinism-harness.adoc[how to run it]).
* Phase 1 CLI demo (SPAC-108): `nix develop -c cargo run -p phase1-demo` loads the PD-31 speed envelope from `assets/space_envelope/pd-31.ron`, prints the validated values with figures a person can picture, runs a deterministic `st-sim` replay built from the same data and prints its state hash. Saving the file reloads it through `st_game::HotData`; a bad edit prints the error with file, line and column and keeps the old values. It is a dev tool that enables `hot-reload` itself, so the game binary carries no watcher. How to try it: xref:try/phase-1.adoc[Try Phase 1].
* Determinism comparison (SPAC-125): the four producer jobs upload `determinism-<platform>`, the new `determinism` job compares the four files with each other and with the reference and reports the first diverging scenario and tick; the harness has the x86_64 Linux leak detector (exit status 3) and `--dump-tick`. `determinism` is the tenth required check.
* The flake keeps `.ron` data files in its source filter (PR #22).
* Docs: the xref:../index.adoc[index] and stubs, ADRs 0001 to 0010, the product decision records PD-01 to PD-34, `AGENTS.md`, `README.adoc` and the xref:../60-contributing.adoc[contributing guide].

== Known problems

* The golden tests of `st-math`, `st-rng`, `st-time`, `st-sim` and `st-data` run on `wasm32-wasip1` under wasmtime in the `wasm32` job.
